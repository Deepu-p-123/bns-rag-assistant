# ⚖️ BNS Legal RAG Assistant — v2 (Chatbot)

A chat-based Retrieval-Augmented Generation assistant for the **Bharatiya Nyaya Sanhita (BNS)**,
built directly from the official BNS PDF instead of a hand-maintained CSV.

## What's new vs. v1

- **PDF as the source of truth** — sections are parsed directly from the official BNS PDF
  (`extract_sections.py`), not a manually curated spreadsheet.
- **Chroma** instead of FAISS — vectors, metadata (section number, chapter, title), and
  documents live together, enabling metadata-filtered search (e.g. restrict to a chapter).
- **Better embeddings** — `BAAI/bge-base-en-v1.5` instead of `all-MiniLM-L6-v2`.
- **Hybrid retrieval + reranking** — exact section lookup, semantic search, and a
  cross-encoder rerank pass for precision.
- **Chat, not single-shot Q&A** — session memory, follow-up-aware query rewriting,
  and a proper Streamlit chat UI.
- **Inline citations** — every answer shows which BNS section(s) it came from.
- **Guardrails** — low-relevance queries get an honest "no match" instead of a
  hallucinated answer, and every answer carries a not-legal-advice disclaimer.

## Project structure

```
bns_rag_v2/
├── data/
│   ├── bns_official.pdf       # you provide this
│   └── sections.jsonl         # generated by extract_sections.py
├── chroma_bns_db/              # generated by build_vectorstore.py (persistent)
├── extract_sections.py         # PDF -> structured sections
├── build_vectorstore.py        # sections -> Chroma collection
├── rag_backend.py               # hybrid retrieval, chat memory, generation

├── requirements.txt
└── .gitignore
```

## Usage

1. **Drop the official BNS PDF into `data/`**, e.g. `data/bns_official.pdf`.

2. **Parse it into sections:**
   ```bash
   python extract_sections.py data/bns_official.pdf --debug
   ```
   Inspect `data/sections.jsonl` afterward. If section counts look wrong (merged,
   missing, or split incorrectly), the regexes in `extract_sections.py`
   (`CHAPTER_RE`, `SECTION_RE`) need tuning to match your PDF's exact formatting —
   this is the one step that depends on the real document and can't be guessed blind.

3. **Build the vector store:**
   ```bash
   python build_vectorstore.py
   ```

4. **Run the chatbot:**
   ```bash
   streamlit run app.py
   ```

## Tuning notes

- **Chunking**: sections are kept whole unless they exceed ~400 tokens, in which case
  they're sub-split with overlap. See `SUB_CHUNK_TOKEN_THRESHOLD` in `extract_sections.py`.
- **Generation model**: `google/flan-t5-base` is the default (fully local, no API key,
  matches v1's constraint). If chat answers feel shallow, swap `GENERATION_MODEL` in
  `rag_backend.py` for a larger local model (e.g. via Ollama) or an API model.
- **Relevance gate**: `MIN_RELEVANCE_SCORE` in `rag_backend.py` controls when the bot
  says "no match" instead of answering — tune it after seeing real query/score behavior.
- **Chapter filter**: exposed in the sidebar; wire more filters into `hybrid_retrieve()`
  the same way if you want to filter by other metadata later.
